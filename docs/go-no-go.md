## 二、议题与决议

### 议题 1：FR-60 帧预算判据口径（✅ **已决：方案 A**，2026-10-18 PM 拍板，本项不再是阻断）

**事实**（2026-10-18 一手实测，详见 LOG「M6 收口包」条与 checklist 差异 #4）：
1. **空白页（0 节点）** 实测 `95% 帧 <16.7ms` 仅 **75.4~86.2%** —— 空画布不可能"未达性能预算"。
2. **零输入静置 3s** 仍仅 86.2%；**仅移动鼠标**即降到 65%（与渲染负载无关）。
3. **CPU Profile（拖拽期）**：主线程 `idle` **2038/2750ms（74%）**，最大应用函数 **25.9ms**，`drawScene` 12.1ms —— **JS 不是瓶颈**。
4. **vsync 量化桶**（真卡顿指标）：优化后拖动 **99.44%** 帧落在 1× vsync 桶、**仅掉 1 帧**。
5. 已实施三项真优化：拖拽层提升 / 悬停幂等 / guides 签名门控 → 真掉帧 **10→0（idle）、11→1（拖动）**。

**归因**：60Hz 下 rAF 间隔≈16.667ms，判据 `严格 <16.7` 仅留 **0.033ms** 余量，任何调度抖动即判负 → **该阈值测的是量化噪声，不是卡顿**。

**候选方案（Dev 提出；PM 2026-10-18 拍板 = 方案 A）**：
- **方案 A（推荐）**：判据改为「**拖拽采样中 ≥95% 帧按时（<1.5×vsync ≈ 25ms）**」，即**掉帧率 ≤5%**。语义与 PRD「95% 帧按时」一致且可测；当前实测 94.4~99.4%（视拖拽强度）。
- **方案 B**：保留 `<16.7ms` 但改为**以空白页基线归一化**（如「达标率不低于空白页基线 − 3pp」）。
- **方案 C**：接受 `avg ≥55fps 且 掉帧率 ≤10%` 的降级口径，并在 PRD 记差异。

**PM 决议**：✅ **方案 A**（2026-10-18，拍板记录已写入 `perf-1000.mjs` decidedBy 字段）——主判据=拖拽采样 ≥95% 帧按时（<1.5×vsync≈25ms）。落地：perf-1000 已切换（含 WARMUP 排除 JIT 启动成本）、实测**按时率 95.27% ≥95% 达标**（掉帧 31/655；idle 60.3fps）、m4-matrix 判据同步复跑 12/12、checklist P1-01 改判 PASS、差异 #4 结案。**行走查 70/70 = 100%**。

### 议题 2：P2 协作 MVP（FR-61）

**范围**（PRD）：分享链接、双浏览器同页实时编辑（多人光标）、冲突合并、断线重连不丢数据；账号/云基础设施为前置（成本与隐私）。

**PM 决议**：✅ **NO-GO（2026-10-18 PM 正式拍板「不做」）**，转 Future Considerations。理由（维持 Dev 建议）：① 与"确定性编译、零后端、数据不出本机"的核心定位冲突；② 无账号/云基础设施预算；③ GA 线（M6）不含协作。若未来翻案按 §四 Future 条件另立里程碑。

### 议题 3：Variables（FR-30，P2）

**现状**：schema 无变量类型；Variables 要求「变量集合 + mode + 绑定到参数（fill/圆角/间距）+ 按 mode 导出 class 变量组」。

**已有替代**：FR-27 四类样式 + FR-28 `tokens.css` 已提供**命名样式 → CSS 变量**的导出能力（PAINT/TEXT/EFFECT/GRID）。Variables 的增量价值 = **mode 切换**（同一 token 多套值）。

**PM 决议**：✅ **NO-GO（2026-10-18，PM「全接受」）**：Tokens 已覆盖 80% 使用场景，mode 属高级特性；登记 Future Considerations。
